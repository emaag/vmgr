## [1.7.0] - 2026-10-18

The multi-drive catalog now handles large libraries, and duplicate copies can be cleaned up across drives.

### Added
- **Clean up duplicates across drives**: after the cross-drive duplicate report, pick a drive and its extra copies are moved to that
  drive's own `.vmgr-trash` (undoable, and the catalog is updated at once). A copy is moved only when an identical copy exists on
  **another drive that is online right now**, and only if both files still match the size and modification time the catalog recorded;
  anything that changed since the scan, or whose other copy is gone, is left alone with a note to rescan. Copies that exist only on
  one drive, or only on an offline drive, are never offered. Dry run previews it.

### Changed
- **Catalog scales to large libraries**: scanning, searching and merging were reworked after a stress test with 20,000 real files and a 200,000-record catalog. First scan of 20,000 files dropped from about 320 s to about 20 s; an unchanged rescan takes about 2 s and leaves the catalog file untouched. Hashing is batched, files are classified in a single awk pass, and the catalog is stored one record per line (still valid JSON; older catalogs are converted automatically). Searching is about 10x faster and merging a small scan into 200,000 records uses about 5 MB instead of about 394 MB.

### Documentation
- The user guide, installation guide and quick reference were brought in line with 1.6.0: new overview and feature list, a quick
  start and first-run walkthrough for the current interface (single-key menus, directory browser, dry-run then apply, undo), a File
  Operations menu section that matches the real screens, the Subtitle Generation and catalog menus, an *Undo and Trash* section,
  rewritten Utilities and Settings sections, the full command table (catalog, Reddit, trash, undo), the FAQ, the version history, and
  the example output (generated by the real program). Tab completion now knows the catalog, Reddit and trash commands.

## [1.6.0] - 2026-10-18

The multi-drive catalog is real (it was a stub), the Reddit downloader no longer leaves empty folders and has a guided API setup,
and log messages stop mangling Windows paths.

### Highlights
- **Multi-Drive Catalog**: scan drives into a searchable, incremental catalog that keeps working when a drive is unplugged, with
  duplicates across drives.
- **Reddit API Setup**: a guided screen that checks your login with Reddit before saving it, to unlock galleries and full speed.
- **Reddit downloader fixes**: no more empty folders, clear reasons when nothing downloads, names validated up front.

### Added
- **Multi-Drive Catalog** (previously a stub): scan a drive or folder into a catalog of every media file with its size, modification
  time, SHA-256 hash and metadata (video/audio resolution, codec and duration via `ffprobe`; image dimensions and camera via
  `exiftool` or ImageMagick). Scans are **incremental**: files whose size and modification time are unchanged are not hashed or
  probed again, and the run reports `new / updated / removed / unchanged`. A scan only changes records under the folder scanned.
  Drives are identified once per mount point (UUID, Windows volume ID, or a hash of the mount point) and paths are stored relative
  to it.
- **Cataloged Drives** lists each drive as online or offline with type, totals, a per-media-type breakdown and last scan.
  **Search** matches names and folders, a hash prefix, an exact resolution or a camera, and includes drives that are offline (marked
  with a hollow dot). **Duplicates** are found across every drive and name the drive each copy is on. **Export** writes a text
  report. Offline drives are forgotten after `CATALOG_OFFLINE_RETENTION` days (0 keeps them).
- **Catalog Several Drives** uses the Batch Processing queue screen and per-drive results list; the scan screen lists detected
  drives (`/mnt/*`, `/media`, `/Volumes`) with free space.
- Catalog command line: `catalog <dir>`, `catalog-list`, `catalog-search <term> [video|image|audio]`, `catalog-duplicates`,
  `catalog-report [file]` (with tab completion). `--dry-run catalog` previews the counts without writing.
- **Reddit API Setup** (Reddit menu > 2, or `vmgr reddit-setup`): a guided screen for the credentials that unlock galleries and
  full-speed downloads. It shows the steps for creating a "script" app (and can open the page), takes the client ID and the secret
  (typed hidden, never echoed or logged), **checks the login with a real token request before saving**, explains a rejection and
  lets you retry, and writes `~/.vmgr-reddit.conf` readable only by you, keeping any other settings in it. With a login already
  saved it can test, replace or delete it. The Reddit menu shows whether a login is saved, and the download screen and the
  "galleries skipped" message point to the setup.

### Changed
- The Reddit token request passes the credentials to `curl` on stdin instead of `-u`, so they no longer appear in the process list.

### Fixed
- **Reddit downloader left empty folders and unclear failures.** The output folder is now created when the first file is about to be
  saved, so a failed request (HTTP 404 for a missing, banned, private or quarantined subreddit; Reddit's 302 redirect for one that
  does not exist) no longer leaves an empty folder behind. A run that saves nothing (a subreddit of galleries, which need API
  credentials, of text posts, or only failures) now says "Nothing was downloaded", explains why, returns a failure instead of
  "Downloaded 0 items", and removes a folder it created. Subreddit names are validated up front (letters, numbers and underscores,
  2-21 characters), so a file path pasted by mistake is refused before any folder is named after it. A 404 now explains that Reddit
  also answers 404 for banned, private and quarantined subreddits; the summary card says "Downloaded N" instead of "Files moved".
- Log messages are printed literally: a backslash in a message (a Windows path such as `C:\Users\emaag`) was treated as an escape and
  mangled by `echo -e`.
- Drive detection: a mount point of `/` was typed "Network" (the check grepped `mount` for `/`, which matches every line) and
  labelled `/`; it is now matched exactly and called "System drive". The drive-id fallback no longer needs `md5sum` (absent on macOS).

## [1.5.0] - 2026-10-18

Duplicate deletion is now undoable, and subtitle generation copes with silence and runs in batches like everything else.

### Highlights
- **Deleted duplicates go to an undoable trash** (`.vmgr-trash`), with **Empty Trash** to delete them for good.
- **Whisper filler is cleaned up**: silent or music-only videos no longer get a subtitle full of `.` cues.
- **Batch Subtitle Generation** uses the same folder queue and per-folder results as Batch Processing.

### Added
- **Trash for duplicates**: "Find and Delete Duplicates" moves the extra copies to a hidden `.vmgr-trash/<timestamp>/` folder
  inside the scanned folder (same drive, so the move is instant, with each file's relative path kept) and records them in the undo
  log, so **Utilities > Undo Last Operation** puts them back. The confirmation is a single-key yes/no; with the Undo System switched
  off it stays a typed `yes` and deletes permanently, as before.
- **Empty Trash** (Utilities > 8, or `--empty-trash`) lists every trash folder the undo logs know about with its file count and size,
  asks before deleting for good, and retires the undo logs that pointed into it (kept as `.log.expired`).
- The summary card reports "Moved to trash" and "To reclaim (empty trash)" for these runs.
- Every recursive scan (duplicates, flatten, image conversion, subtitles, organize) skips `.vmgr-trash`, so trashed files are never
  rediscovered, flattened back out, or transcribed.
- Subtitle generation removes filler cues (`.`, `...`, punctuation only) that Whisper writes over silence and music. When nothing
  but filler is left, no subtitle file is written, the video is counted under "No speech found" on the summary card, and a
  hidden `.<name>.nospeech` marker makes the next run skip it instead of transcribing it again (delete the marker to retry).

### Changed
- **Batch Subtitle Generation** uses the folder-queue screen and per-folder results list of Batch Processing (browse, add every
  subfolder with videos, or type a path) instead of the old `[B] Browse [T] Type` prompt. Whisper is checked once up front, and
  each folder's summary line counts only that folder (it used to repeat the running total). A dry run previews and then offers to
  generate.

### Fixed
- The test suite no longer writes to the real home directory: `core.sh` overwrote the log and undo paths the tests set, so
  tests that rename or flatten files created undo records in `~/.video-manager-logs/undo-history`, where they could shadow a
  real operation for Undo Last Operation. Tests now re-apply their paths after loading `core.sh` and run under a throwaway `HOME`.

## [1.4.0] - 2026-10-18

A redesigned, faster interface plus a safety net: renames and flattens can now be undone, batch processing is
reachable and asks before it changes anything, and the output is quiet by default.

### Highlights
- **Undo for renames and flattens**, single or batch (Utilities > Undo Last Operation).
- **Batch Processing** (File Operations > 7) with a folder queue, preview, confirmation, progress and a per-folder results list.
- **New look**: framed header, single-key menus, a themed directory browser, progress bars and a summary card after every operation.
- **Quiet by default**; `--verbose` brings back the per-file detail.
- Many screens that used to flash past and vanish now wait for a key.

### Added
- **Undo for renames and flattens**: Rename Files, Remove Dashes, Fix Bracket Spacing, Flatten and their batch versions
  record every change in an undo log (one per operation; a batch is one operation) and print how many changes were recorded.
  Utilities > Undo Last Operation (and the granular-controls entry, which called a function that did not exist) puts them back,
  List Undo Operations shows each operation by name with its file count, and `--undo-organize [ID]` accepts any logged
  operation. Dry runs and `Undo System: off` record nothing; duplicate deletion and image conversion are not recorded.
- **Batch Processing and Automated Workflows are reachable** from File Operations (7 and 8); both were previously unreachable
  from the menu. Batch builds a folder queue with live video counts (add with the browser, add every subfolder that has videos,
  or type a path), previews when dry run is on, asks for confirmation before changing files, shows a per-folder header with an
  overall progress bar, and ends with a per-folder Results list. Cancelling returns straight to the menu. Workflows also confirm
  before running and show the operation banner and summary card. `vmgr batch` keeps reading one directory per line when input
  is piped.
- **Batch Find Duplicates** (report only, per folder).
- **Menu redesign**: a framed header with a status strip (dry-run state and the selected folder), compact one-line menu items
  with colored key chips and dimmed descriptions, on/off dots for toggles, and grouped sections. New `lib/theme.sh` holds the
  shared helpers (`ui_title`, `ui_item`, `ui_item_toggle`, `ui_kv`, `ui_section`, ...).
- Menus take a single keypress (no Enter); `Esc` goes back, arrow keys are ignored, and end of input leaves the menu instead
  of looping. Sub-screens and prompts share the look: `show_screen`, `ui_confirm` (single-key y/n; Enter takes the default,
  Esc means no), `ui_ask` for text, `ui_pause` (any key). `ask_yes_no` / `pause_for_key` in `core.sh` fall back to plain
  prompts when `theme.sh` is not loaded.
- **Progress and results**: operations open with a `▶ Name` banner (with a DRY RUN badge) and close with a summary card whose
  title reflects success, a dry run, or the error count, listing only the non-zero statistics and the duration. Rename-style
  loops, duplicate hashing, organize and undo show an in-place progress bar (terminal only) and compact `old → new` pairs; the
  subtitle run's per-file header is a compact `▶ name [3/10] ETA 2m5s` with a bar. Everything falls back to the previous
  output when `theme.sh` is not loaded.
- 256-color palette when the terminal supports it. `NO_COLOR` / `TERM=dumb` print no escape codes, and a non-UTF-8 locale
  (or the linux console) uses ASCII glyphs.
- **Directory browser rewrite** (`lib/browser.sh`, moved out of `ui.sh`): arrow-key navigation (↑↓ move, → open, Enter choose
  the highlighted folder, ←/Backspace up, PgUp/PgDn, Home/End), in-place repainting, scrolling for long lists, a two-column
  layout with a live preview of the highlighted folder, and a framed header with counts and hidden-folder state. Narrow
  terminals (<70 cols) show one column. Shortcuts: `S`/Space choose the `Location:`, `~` home, `-` previous directory, `R`
  recent directories (`~/.video-manager-recent-dirs`), `.` hidden folders, `T` type a path with Tab completion, `F` refresh.
  Directory listings are cached per folder (validated by mtime). Symlinks and Windows junctions are not listed (use `T`). It
  redraws without forking subprocesses and paints once for a burst of keys (60 queued keypresses: 6.0s to 0.4s). It starts in
  your most recent folder, or on a first run in `~/Videos`, `~/Movies` or your Windows `Videos` folder under WSL, and tells you
  to press `T` when it opens on an empty folder. It falls back to a plain prompt when stdin/stdout is not a terminal.
- `--verbose` flag (`-q`/`--quiet` still accepted).

### Changed
- **Quiet by default**: verbose output is off, so the per-file intermediate steps ("After dash removal", ...) no longer bury the
  before/after results. Use `--verbose` or Settings > Toggle Verbose Output; a saved config keeps whatever it stored.
- The "Loading ... modules" line no longer prints before `--help` and the menu.
- Duplicate reports are written to `~/.video-manager-logs/duplicate-reports/<folder>_<timestamp>/` instead of a
  `_duplicate_report_*` folder inside the scanned collection (still the fallback if the logs directory is not writable). A
  scan that finds nothing leaves no empty report folder behind. Duplicate groups print as
  `Group 1 · 3 copies · 2.9MiB each` with keep/extra lines and paths relative to the scanned folder (the full hash stays in
  the report file), and sizes show units.
- Duplicate scans are sorted, so the copy that is kept is always the first alphabetically.
- Dry runs report how many files *would* be renamed.
- Subtitle settings choose the model and format with a single keypress; the remaining old-style screens (subtitle filters,
  catalog settings and search, organize settings, filename test, whisper install help) use the themed rows and sections.

### Fixed
- Screens that flashed past and vanished now wait for a key: Supported Extensions, System Information, Last 50 Log Entries,
  Undo History, the Whisper check, the duplicates report and dry run, catalog list/duplicates, list undo operations,
  List/Delete Profiles, catalog and filter settings, and error exits such as an empty mount point or a missing `jq`.
- Each operation reports its own statistics: `start_operation` resets the counters, so an Apply step no longer inherits the dry
  run's numbers, and the Apply step runs with dry run off so its banner and card no longer say dry run.
- Log messages wipe a live progress bar first, so a stale `Processing ███ 66%` row no longer stays on screen.
- A mistyped menu key flashes "Invalid option" once and redraws; it was printed twice and needed an extra keypress.
- The Whisper check runs the command and reports a broken install in one line instead of printing a Python traceback.
- **Browser paths**: going into a folder from `/` produced `//mnt/...`; leading `//` is now collapsed.
- **Destructive-op prompt**: `grep -c ... || echo 0` yielded `0\n0` when nothing matched, printing
  `[[: 0 0: syntax error` before "Proceed?". The prompt also now explains when videos exist only in subfolders (Rename and
  similar operations only look at files directly in the folder).
- **Reddit downloads without API credentials**: Reddit now returns HTTP 403 for unauthenticated `.json` requests. Without
  `~/.vmgr-reddit.conf` the downloader now uses the public RSS feed instead (images, gifs, direct video links, and `v.redd.it`
  videos resolved through the DASH manifest and muxed with audio). With credentials it still uses the OAuth API.
- HTTP 429 rate limiting is waited out using the `Retry-After` / `X-Ratelimit-Reset` headers (up to `REDDIT_MAX_RETRIES`
  times, at most `REDDIT_MAX_WAIT` seconds each) instead of failing.
- Failures now report the real HTTP status and a plain-language reason instead of a generic "Failed to fetch" message.
- A page with no downloadable media no longer ends the run while more pages remain.
- **Reddit galleries**: with API credentials every valid image in a gallery (including crossposted galleries) is downloaded
  from its original `i.redd.it` file. The RSS feed does not list gallery images, so without credentials galleries are skipped
  and a summary says how many.

### Documentation
- User guide and quick reference cover the directory browser keys, batch processing, undo, the Reddit downloader (credentials,
  RSS fallback, galleries), `--verbose`, and where duplicate reports go.

## [1.3.0] - 2025-12-23

### 🎉 Major Architectural Transformation

This release represents a **complete refactoring** of the video manager from a monolithic script to a clean, modular architecture.

### Added

- **Modular Architecture** - Split into 12 independent, testable modules:
  - **Phase 1 - Foundation** (896 lines)
    - `lib/core.sh` - Core initialization and constants
    - `lib/platform.sh` - Cross-platform compatibility
    - `lib/logging.sh` - Logging and progress tracking
    - `lib/config.sh` - Configuration management
  - **Phase 2 - Core Features** (1,942 lines)
    - `lib/utils.sh` - Utility functions and file type detection
    - `lib/file-ops.sh` - File operations and renaming
    - `lib/duplicates.sh` - Duplicate file detection
    - `lib/organize.sh` - File organization and undo system
  - **Phase 3 - Advanced Features** (2,024 lines)
    - `lib/subtitles.sh` - Whisper AI subtitle generation
    - `lib/catalog.sh` - Multi-drive catalog system
    - `lib/batch.sh` - Batch processing and workflows
    - `lib/ui.sh` - Interactive menu system (1,577 lines)

- **Comprehensive Test Suite** - `test-modules.sh` with 26 tests (100% pass rate)
- **Enhanced Tab Completion** - Updated for all commands including organize operations
- **Improved Documentation** - Added modularization progress tracking

### Changed

- **Main Script Size** - Reduced from 6,590 lines to 465 lines (93% reduction)
- **Architecture** - Clean separation of concerns with documented dependencies
- **Maintainability** - Each module focused on single responsibility
- **Entry Point** - Main script now loads modules and orchestrates execution

### Fixed

- Tab completion now includes all organize commands (`--organize`, `--organize-target`, `--organize-search`, `--undo-organize`, `--list-undo`)
- Module loading with proper error handling
- All functionality preserved from previous versions

### Technical Details

**Metrics:**
- Main script: 6,590 → 465 lines (93% reduction)
- Total modules: 4,869 lines across 12 files
- Test coverage: 100% (26/26 tests passing)
- Modules completed: 12/12 (100%)

**Benefits:**
- ✅ Better maintainability
- ✅ Easier testing
- ✅ Clear code organization
- ✅ Simpler to extend
- ✅ Reduced complexity

**Preserved Functionality:**
- All CLI commands working
- Interactive menu fully functional
- Organize/undo operations working
- Subtitle generation working
- All original features intact

### Migration Notes

For users upgrading from v1.2.0:
- No breaking changes - all commands work exactly as before
- Legacy versions preserved as backups:
  - `video-manager-ultimate-legacy.sh` (original)
  - `video-manager-ultimate-monolithic.sh` (pre-refactor)
- Tab completion may need to be re-sourced: `source ~/.bash_completion.d/vmgr`
